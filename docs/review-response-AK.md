# A–K 复核回复

对照 dots（八嘎）的 A–K。实现上全部接受。没有把 510310 的跳变门槛从 20% 抬高。下面每条写的是代码和单元测试里已经做的事。

这些事没有做，也不能从这次修订里读出来：

- 没有新的现场抓取。2026-10-16 的 `docs/live-smoke.md` 仍是当时那一轮。
- 没有观察到真实的晚间份额到次日早间被修订。这个对照只在夹具里。
- 没有做 120 日份额回补，也没有做知识截止日期回放。
- 影子试验参数仍是空的。`sim-check` 退出码 2。账本写入仍被拒绝。
- 没有把份额变化写成国家队资金。

补充（库结构）：`Store` 打开时会迁移 2621ca0 时代的旧库——给 `raw_fetches` / `observation_versions` 补齐新列，并写入 `schema_version`。已有原始正文路径和观察版本原样保留，不会删库重建。

## A. 接受

原始正文按 SHA-256 放在 `data/raw/by-hash/`。文件已存在就不再写。每次真实请求、每次重试各有一行 `raw_fetches`。观察版本的 `raw_fetch_id` 指向产生该正文的网络抓取，不指向后来的缓存读取。

`network_fetched_at`、`cache_accessed_at`、`observation_available_at` 分开存。缓存命中不改正文，也不把有效期改成读取时间。入库用该次响应的到达时间，不用整轮任务开始时的同一个 `now`。

补充（c340e2c 之后）：`http_client` 在 `_once` **之前**记 `request_started_at`，在 `_once` **返回之后**再取 `network_fetched_at`。transport 里推进时钟的测试要求这两点不同；不能把发请求时刻当成响应完整到达。

补充（跟进）：真实 E2E 覆盖「缓存命中 → attach_fetch / 适配器 → ingest」跨 08:00；以及「09:34:59 发请求、09:35:10 到达」联合断言——`network_fetched_at` / `observation_available_at` 取到达时刻，`assert_entry_after_data(09:35:00, …)` 拒绝排程。旧库 `raw_fetches.network_fetched_at` 为 NULL 时不把 `fetched_at` 当可靠到达时间：即使按 `fetched_at` 仍在 TTL 内也强制重新请求，不回填历史戳。

## B. 接受

`--session` 和 `--phase` 只表示意图。阶段由数据日、当天日历和钟点决定，请求不能把阶段抬成更权威。

配置里的 08:00 只是分界：07:59 仍是 `overnight` 且不权威；08:00 按配置可以标 `morning`。这不是交易所已经发布权威份额的保证。未来日期、周末或休市隔开的日期，即使用 `--phase morning` 也仍是 `future_invalid` 或 `backfill`。

补充：判阶段用「正文可得时间」（`observation_available_at` / `network_fetched_at`），不用批次 `now`。跨 08:00 的缓存命中：07:50 的原文在 08:01 入库仍是 `overnight`，不能误升 `morning` / 权威。 另有经 HttpClient 缓存 + `collect_sse`/`attach_fetch` + `ingest_points` 的端到端反例。

## C. 接受

份额差只用相邻上一交易日。缺了这一天时，更早的非空值不能顶上，也不产生当日流量。相邻日若是异常跳变或其他不可用状态，当日也不做差。20% 和 50% 的门槛没有改。

交易日历仍然只有周末自动判断，加上配置里的休市日。`config/example.toml` 的休市表继续是空的，没有把 2026 年国庆写成已经核对的假日。窗口若盖住 2026-10-01 至 10-07 的工作日而表里没有这些日期，完整性检查失败，检查点不能是 `complete`。

## D. 接受

更早一天的份额被修订或补录后，其后日期按新的相邻值重算质量和标志，并追加版本。旧版本的状态原样留下。`quality_events` 里有 `dependent_recalc`。

## E. 接受

易方达翻页看响应里的 `pageIndex`、`pageSize`、`total` 和本页**唯一日期**，不看请求里的 `pageSize`。物理行数不能替代唯一日期。重复页（日期与先前页重叠）、`total` 中途缩小等 metadata 异常一律记不完整，绝不当成完成。提前出现空页，或唯一日期少于 `total`，也记为不完整。测试用三页共 60 个日期，请求 page size 为 150，仍会请求 0、1、2 页；另有重复页与 total 缩小的反例。

## F. 接受

检查点分成 `complete`、`waiting_update`、`incomplete`。没有 HTTP 错误但有缺口时是 `waiting_update`，下一轮不加 `--force` 也会再跑。只有 `complete` 才跳过。测试先缺一天，再补上。

## G. 接受

拒绝 NaN、Inf、非正单位净值和负份额。坏日期、坏页码记在该来源、该页或该行上，不把整次 `collect` 打崩，也不在吞掉坏行之后把检查点标成完成。SSE `result=[null]`、易方达 `data.data=[null]` 等坏结构会校验容器/行类型并记错误，其它来源继续；检查点不能是 `complete`。

## H. 接受

每次重试都留下状态、正文和时间。同一主机的重试等待不短于配置的最小间隔。测试覆盖 503 然后 200、超时然后 200，以及 10 秒最小间隔。

## I. 接受

华夏和嘉实的 HTML 按单元格各自解析，不再依赖整行正则。日期和单位净值有效时，累计净值是 `--` 或 `N/A` 也保留单位净值。单位净值空白或缺 `--` 时走缺失分支，不拿累计净值填进去。

## J. 接受

5 日指标的分母是窗口第一天之前那个交易日的四只（份额 × 单位净值）之和，不是窗口内第一天。协议和数值夹具都写了 2026-10-12 那周，分母日是 2026-10-09，规模是 3000，而不是第一天自己的规模。

## K. 接受

80 分位先按时间排序，只用最近 120 个已完成指标。121 个和 240 个样本都不会把更早的值算进这 120 个。不足 120 个仍然拒绝。
